# Requirements Analysis

当用户要做需求分析、需求调研、规则澄清或在写 PRD 之前先把问题分析清楚时，使用本命令。

## 目标

把模糊需求转成结构化的分析文档，默认放到对应专题的 `analysis/` 目录。

## 执行要求

1. 优先阅读当前专题已有材料，而不是凭空分析。
2. 输出尽量包含：
   - 需求背景
   - 目标确认
   - 现状流程
   - 目标流程
   - 功能拆解
   - 待确认事项
3. 涉及流程时优先使用 Mermaid。
4. 没有确认的信息必须显式写“待确认”，不要自行编造。

## 落位规则

- 正式分析文档：`04_workspace/prd/某个专题/analysis/`
- 若主题未明确：先放 `05_drafts/方案探索/`
