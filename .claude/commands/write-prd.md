# Write PRD

根据当前仓库中的 `03_context/`、`04_workspace/`、`05_drafts/` 内容，为指定需求撰写一份高质量 PRD。

## 使用目标

当用户提出一个新需求、功能改动、流程优化或业务方案，并希望输出正式 PRD 时，使用本命令。

## 执行要求

1. 先阅读与需求相关的上下文，而不是直接开写。
2. 优先从以下位置获取背景：
   - `03_context/01_产品架构/`
   - `03_context/02_功能模块/`
   - `03_context/05_架构决策/`
   - `04_workspace/discussions/`
   - `04_workspace/关键会议纪要/`
3. 如果上下文不足，明确列出缺口，不要编造业务事实。
4. 输出内容应结构清晰、可评审、便于研发和协作方理解。
5. 默认使用中文输出，除非用户明确要求英文。

## PRD 输出结构

必须尽量包含以下部分：

- 背景
- 问题定义
- 目标
- 非目标
- 用户场景
- 方案说明
- 关键流程
- 规则与边界条件
- 数据与指标
- 风险与依赖
- 待确认问题

## 文件落位规则

- 正式 PRD 放到 `04_workspace/prd/`
- 如果仍处于探索阶段，可先写到 `05_drafts/方案探索/`
- 输出完成后，建议同步更新相关目录的 `CLAUDE.md`

## 输出风格

- 不写空话，不写口号式表达
- 用产品团队能直接评审的语言
- 对模糊点用 `[TODO]` 或“待确认”显式标记
- 如果需求范围过大，先拆分模块再写

## 推荐行为

- 若用户只给了一句话需求，先基于现有 context 补出 PRD 初稿
- 若存在历史类似需求，主动参考并复用已有结构
- 若涉及已上线能力，说明与现有系统的关系和影响范围
