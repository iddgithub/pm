# pm_agent 目录说明

## 1. 定位

`pm_agent` 是当前产品经理主仓中的 Context 知识底座，也是后续默认的长期记忆载体。

它的目标不是只存资料，而是把产品经理工作中会反复使用的信息按稳定程度组织起来，让 AI 和人都能快速找到、复用和持续维护。

## 2. 总体结构

仓库按三层知识流转结构组织：

```text
pm_agent/
├── .claude/commands/
├── 03_context/
├── 04_workspace/
└── 05_drafts/
```

知识流转路径为：

`05_drafts/` -> `04_workspace/` -> `03_context/`

含义如下：

- `05_drafts/`：还没想清楚、先记下来
- `04_workspace/`：正在推进、正在评审、正在执行
- `03_context/`：已经确认、可复用、相对稳定

## 3. 各目录职责

### 3.1 `.claude/commands/`

用于存放标准化技能与命令入口，可通过 `/skill-name` 方式调用，服务于更稳定的协作流程。

### 3.2 `03_context/`

知识库层，存放已经确认的事实和长期可复用信息。

子目录职责：

- `01_产品架构/`：产品框架、术语表、立项背景等基础产品上下文
- `02_功能模块/`：已经实现功能的详细设计与功能说明
- `03_运营材料/`：帮助手册、官网素材、客户沟通材料
- `04_参考附录/`：行业标准、威胁知识库、客户标书等参考资料
- `05_架构决策/`：ADR 和关键架构决策记录
- `06_团队信息/`：团队成员、角色分工与协作信息

其中，后续应重点维护：

- `01_产品架构/`
- `02_功能模块/`

这两个目录是支持产品经理日常工作的核心稳定上下文。

### 3.3 `04_workspace/`

工作区层，存放当前正在做的事。

子目录职责：

- `prd/`：产品需求文档，可按阶段继续细分
- `bugs/`：Bug 记录，可按负责人或状态组织
- `discussions/`：大需求讨论记录
- `公众号/`：公众号内容与选题产出
- `关键会议纪要/`：重要会议记录

适合放入这里的内容包括：

- 新需求 PRD
- 原型方案
- 正在评审的后台需求
- 会议后的行动项与讨论结论
- 尚未沉淀为稳定事实的阶段性方案

### 3.4 `05_drafts/`

草稿区，存放还没想清楚的内容，作为最低门槛输入区。

子目录职责：

- `临时记录/`：灵感、碎片信息、快速笔记
- `方案探索/`：方向性方案、开放问题、尚未收敛的思路

## 4. 后续维护约定

为更好支持产品经理工作，后续默认遵循以下约定：

1. 新需求优先进入 `04_workspace/prd/`。
2. 大需求讨论优先进入 `04_workspace/discussions/`。
3. 会议结论若已明确行动方向，可进入 `04_workspace/关键会议纪要/`。
4. 还未收敛的思路先进入 `05_drafts/`，避免把不稳定信息直接写入 `03_context/`。
5. 一旦需求上线、规则稳定、可长期复用，应从 `04_workspace/` 提炼后沉淀到 `03_context/`。
6. 每次新增重要文件后，都应同步更新对应目录的 `CLAUDE.md` 索引。

## 5. 对产品经理工作的支持重点

后续维护这套仓库时，优先服务以下场景：

- 记录和整理 PRD
- 沉淀功能设计与版本演进
- 保存后台需求评审结果
- 整理会议纪要与讨论结论
- 统一产品术语、产品边界与架构认知
- 为后续 AI 协作提供稳定上下文

因此，`pm_agent` 不只是文档目录，更是产品经理工作的长期知识底座。
