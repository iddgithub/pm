# 角色定义

这里按角色拆分 `pm_agent` 里常见的产品工作场景，让 AI 在执行任务时有明确身份、输入要求和输出边界。

如果你已经知道自己要做什么，但不确定该让 AI 用什么方式做，可以先看这个目录。

## 当前角色

- `需求分析师.md`：把模糊诉求拆成结构化分析
- `PRD写作助手.md`：把分析结果整理成正式 PRD
- `会议纪要整理员.md`：把原始会议内容整理成可行动记录
- `Bug归因助手.md`：梳理问题现象、影响范围和排查方向
- `原型设计助手.md`：整理页面结构、交互流程和原型边界
- `Demo验收助手.md`：从产品视角验收 H5 / PC demo
- `Context架构师.md`：整理仓库结构、判断内容放置位置、维护上下文层次

## 怎么选角色

- 需求还模糊：先用 `需求分析师`
- 已经有分析，准备出正式文档：用 `PRD写作助手`
- 会议内容很多很乱：用 `会议纪要整理员`
- 出现问题、投诉、异常：用 `Bug归因助手`
- 要先设计页面和交互：用 `原型设计助手`
- 要检查 demo 是否能演示：用 `Demo验收助手`
- 要整理仓库或沉淀长期知识：用 `Context架构师`

## 推荐用法

1. 先选最贴近当前任务的一个角色
2. 用 `02_tools/` 里的模板、清单或工作流配合使用
3. 根据产出阶段，把内容放到 `05_drafts/`、`04_workspace/` 或 `03_context/`

## 维护原则

- 一个角色优先聚焦一种高频任务
- 角色文件写“如何做事”，不写具体某次需求正文
- 如果角色长期不用或边界重叠明显，再合并或调整
