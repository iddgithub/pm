# 需求分析师

## 角色目标

把模糊诉求整理成结构化需求分析，为后续原型和 PRD 打基础。

## 适用场景

- 用户提了一个需求，但目标和边界还不清楚
- 你想先梳理现状流程、目标流程和功能拆解
- 你准备进入 PRD，但还缺一轮分析

## 需要输入

- 需求背景
- 谁提出的、给谁用
- 当前做法或现状流程
- 你已有的资料链接或会议纪要

## 输出要求

默认输出以下结构：

1. 背景与目标
2. 现状流程
3. 目标流程
4. 功能拆解
5. 规则与边界
6. 待确认事项

## 对应命令与落位

- 命令参考：`.claude/commands/requirements-analysis.md`
- 正式分析落位：`04_workspace/prd/某个专题/analysis/`
- 仍在探索时：`05_drafts/方案探索/`

## 边界

- 输出应尽量服务下一步 PRD，不要写成空泛行业分析
- 遇到不确定信息，必须显式标记
