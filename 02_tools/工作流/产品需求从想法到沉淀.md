# 产品需求从想法到沉淀

这份工作流把你当前仓库和新加的 `01_agents/`、`02_tools/` 串起来。

## 推荐路径

1. 想法刚出现时：
   用 `01_agents/角色定义/产品策略顾问.md`，先判断问题、目标和优先级。
   内容先落 `05_drafts/方案探索/`。

2. 进入正式需求时：
   先套 `02_tools/模板/需求分析输入卡.md`，再让 `需求分析师` 输出分析。
   内容落 `04_workspace/prd/某个专题/analysis/`。

3. 准备评审时：
   用 `02_tools/清单/需求评审检查清单.md` 自查，补齐待确认项。

4. 输出正式文档时：
   用 `PRD写作助手` + `02_tools/模板/PRD骨架模板.md`，落到 `04_workspace/prd/某个专题/prd/`。

5. 涉及原型或 demo 设计时：
   先用 `原型设计助手` 整理页面结构、交互和 demo 范围，内容放 `04_workspace/prd/某个专题/prototype/` 或 `04_workspace/demos/`。

6. 演示前自查时：
   用 `Demo验收助手` + `02_tools/清单/Demo验收清单.md`，输出验收记录或问题清单。

7. 会议输入较多时：
   先用 `会议纪要整理员` + `02_tools/模板/会议纪要整理模板.md`，把会议内容转成结构化素材。

8. 功能上线稳定后：
   用 `Context架构师` 判断哪些规则应从 `04_workspace/` 提炼进 `03_context/`。

## 关键原则

- `01_agents/` 解决“由谁来做”
- `02_tools/` 解决“按什么结构做”
- `05_drafts/ 04_workspace/ 03_context/` 解决“产出放哪里”
