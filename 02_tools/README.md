# 02_tools

`02_tools/` 用来存放可以反复复用的模板、清单和工作流。

如果说 `01_agents/` 解决“让 AI 以什么身份做事”，那么 `02_tools/` 解决“做事时套用什么结构”。

## 目录关系

- `模板/`：适合复制后直接开工的输入模板和文档骨架
- `清单/`：适合评审、自查、验收时快速过一遍的 checklist
- `工作流/`：适合把一类任务从开始推进到完成的步骤说明

## 当前内容

- `模板/需求分析输入卡.md`：在需求分析前先补齐上下文
- `模板/PRD骨架模板.md`：正式 PRD 的基础结构
- `模板/会议纪要整理模板.md`：把原始会议内容整理成结构化纪要
- `清单/需求评审检查清单.md`：评审前检查目标、范围和规则
- `清单/Demo验收清单.md`：演示前检查页面、流程和状态一致性
- `工作流/产品需求从想法到沉淀.md`：把一个需求从想法推进到文档沉淀的推荐路径

## 推荐用法

1. 先判断当前任务属于分析、写作、验收还是整理
2. 再从 `模板/`、`清单/`、`工作流/` 中挑最贴近的一份结构来套用
3. 配合 `01_agents/` 里的角色定义一起使用
4. 根据产出阶段，把结果放到 `05_drafts/`、`04_workspace/` 或 `03_context/`

## 和其他目录的边界

- `01_agents/`：定义“由谁来做”
- `02_tools/`：定义“按什么结构做”
- `04_workspace/`：存放“正在推进的产出”
- `03_context/`：存放“已经稳定的知识”

## 维护原则

- 工具文档要短、直接、可复制，不写空泛理论
- 优先保留高频使用的模板和清单，不追求铺满所有场景
- 如果某份文档已经变成专题内容，应迁回 `04_workspace/`
