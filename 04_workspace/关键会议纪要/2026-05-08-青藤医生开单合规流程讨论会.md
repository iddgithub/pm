- 会议目标：确认医生开单、互联网医院问诊、报告解读、医生服务费结算之间的合规产品链路

## 背景与原方案

原方案围绕“线下医生推荐患者做检查 + 患者进入青藤/互联网医院链路下单 + 检查后报告回流给同一医生做解读 + 平台按报告解读服务费结算给医生”展开。

原链路大致为：

1. 医生注册青藤平台。
2. 患者线下就诊时，医生通过 H5 开单页录入病情、病史、检查建议、推荐机构等信息。
3. 系统生成互联网医院问诊二维码，患者扫码进入互联网医院问诊并下单支付。
4. 患者线下完成检查，平台生成报告。
5. 报告解读订单分配给原线下推荐医生。
6. 医生完成报告解读，患者查看解读并评价，平台按解读订单向医生结算服务费。

该方案的核心风险是：线下医生推荐患者与后续报告解读服务费存在明显 1:1 对应关系，容易被理解为平台向医生支付“推荐费 / 开单费”，而不是为真实报告解读服务支付劳动报酬。

## 关键结论

### 1. 报告解读不再按“谁推荐谁解读”做 1:1 回派

会议最终倾向确认：报告解读任务应做交叉分配，医生解读的患者不应与自己线下推荐的患者形成 1:1 对应。

- 涂丰涛认为交叉解读比 1:1 对应的合规风险更低，但不代表绝对无风险。
- 陈俊明确要求：医生做报告解读时，尽量看外地或非自己推荐的患者报告，不要和自己推荐来的病人产生对应。
- 袁戎确认：交叉分配不是技术问题，技术上可以实现，关键是业务规则要统一。
- 李飞宇补充：是否必须外省不是重点，重点是后台规则上不要让解读对象和医生推荐对象 1:1 对应。

产品口径应从“来源医生回流解读”改为“平台向医生派发报告解读服务任务”。医生获得的是解读服务劳动报酬，不是患者推荐报酬。

### 2. 医生自己的患者报告查看需求，要与解读结算链路分离

医生确实有看报告和继续完成诊疗的需求，但会议认为这不应放在“付费报告解读任务列表”里解决。

新的边界是：

- 医生为了继续看病，需要查看自己患者的影像和报告。
- 这部分可沿用线下运营现有做法，例如运营人员把报告和影像链接通过微信等方式反馈给医生，或由患者复诊时出示报告链接。
- 医生领取平台报告解读服务费，则通过另一条“交叉派发的报告解读任务”完成。

因此，产品上要拆成两张皮：

- 患者诊疗/报告回看：用于看病，不直接产生医生服务费。
- 报告解读任务：用于平台派单和服务费结算，不与医生自己的患者 1:1 绑定。

### 3. 患者进入青藤平台的动作要弱化“医生直接推介”痕迹

原方案中，医生直接展示个人二维码让患者扫码进入互联网医院问诊，会议认为这个动作过硬，容易被认定为医生对患者进行商业推荐。

建议改成“两条线”：

- 医生端：医生在自己的页面或电脑上录入患者姓名、手机号、身份证、病情描述、检查建议、检查项目等信息。
- 患者端：患者用自己的手机独立进入青藤平台，可通过通用二维码、搜索平台、桌面公共二维码等方式进入。
- 后台绑定：患者进入后填写或授权手机号、姓名、身份证等信息，系统自动匹配医生端预录入的信息，减少患者重复填写。

该改法的目标不是完全消除业务关联，而是避免“医生拿个人码让患者扫”的强证据链，让患者看起来是在自主选择平台和机构。

入口形式仍需胡高鹏继续向一线医生、景璇/薛景璇及相关医药推广经验人员确认。

### 4. 支付应前置，先收钱再提供后续问诊/检查服务

会议后段讨论了支付主体与支付时点。最终口径是：原则上先支付，再继续进入后续互联网医院问诊、检查履约和报告服务。

需要注意的产品细节：

- 患者在支付前必须能看到检查项目、检查机构、价格等关键信息。
- 检查项目原则上来自线下医生预录入的检查建议。
- 若患者后续更换机构或项目，可通过多退少补、取消重下等方式处理。
- 产品表述上不要让患者感觉“一扫码就被强制付款”，需要先让患者看到项目和平台服务信息，再进入支付。

### 5. 收费主体分阶段处理

会议确认了短期和长期两个阶段：

- 短期：在自有互联网医院资质未拿到前，平台定位为撮合平台，以代收代付方式先承接收费；互联网医院相关医疗动作借助已有主体解决。
- 长期：自有互联网医院牌照拿到后，应统一由互联网医院主体收款，再向交付中心、平台、医生等主体进行分账或采购服务结算。

后续可能需要补充或重签交付中心协议，确保收费、开票、采购服务和医疗行为主体一致。

### 6. 报告解读页面要弱化医生签名，但保留服务记录

报告解读不应做成强医疗诊断报告，也不建议突出医生手写签名。

会议形成的页面方向：

- 不做醒目的医生签名。
- 医生姓名、身份信息可以弱化展示，作为服务记录的一部分。
- 页面重点展示报告解读内容，而不是突出医生个人。
- 报告解读应形成一来一回的服务记录，患者可查看医生回复，也可评价服务。
- 参考京东互联网医院等平台的报告解读服务样式。

### 7. 医生注册需要自己提交资质，平台审核

会议确认互联网医生注册应由医生本人登录并提交资料，不宜完全由后台代录。

注册审核方向：

- 医生或医务工作者需要提交手机号、实名信息、执业信息、证书材料等。
- 后台人工审核后，才允许成为可承接报告解读任务的医生。
- 护士、医务工作者等可能存在推荐或引流场景，但只有具备相应资质的医生才能承接报告解读服务。

## 胡高鹏接下来要做什么

### 1. 修改产品方案和 PPT

胡高鹏需要把原方案从“原医生回流解读”改成“前链路弱关联 + 后链路交叉派单”的合规方案。

重点调整：

- 去掉医生直接展示个人问诊二维码给患者扫码的强路径。
- 增加医生端预录入信息、患者端自主进入平台、后台自动匹配的两条线方案。
- 将待解读报告列表改为平台交叉分配的报告解读任务列表。
- 不再表达“医生推荐几个患者，就回派几个自己的患者报告给他解读”。
- 患者报告查看与医生解读结算分离。

### 2. 继续调研入口形式

胡高鹏需要向景璇/薛景璇、一线医生，以及熟悉医药代表/医疗推广的人确认：

- 诊所、民营机构、三甲医院分别能否摆放第三方平台二维码。
- 医生口头推荐、桌面公共二维码、患者自主搜索平台等方式的接受度。
- 医生最能接受的患者进入平台方式是什么。
- 哪些表达会让医生担心被认定为商业推介。

### 3. 和袁戎确认交叉派单规则

需要继续确认：

- 交叉派单是否必须跨省，还是只要不与医生自己推荐患者 1:1 对应即可。
- 医生端能看到哪些患者信息，哪些字段需要匿名或脱敏。
- 任务数量如何与医生服务费金额对齐。
- 任务列表是否按检查项目、解读难度、服务费标准进行匹配。

### 4. 调整报告解读原型

胡高鹏需要调整医生端与患者端原型：

- 把“待解读报告”改为更中性的报告解读任务列表。
- 删除或弱化医生签名，不突出医生个人品牌。
- 保留医生服务记录、患者评价和解读内容。
- 医生操作要足够轻，尽量保持“一键确认 / 少量修改”的低成本模式。

### 5. 补充支付与主体方案

需要把以下口径写入方案：

- 患者先确认检查项目、机构和价格，再支付。
- 支付后进入互联网医院问诊、检查履约和报告服务。
- 短期平台代收代付，长期互联网医院主体统一收款和分账。
- 相关协议和开票逻辑需要财务、法务继续确认。

### 6. 输出运营使用说明和合规话术

陈俊要求胡高鹏后续输出一份面向运营的使用说明，最好按角色维度整理。

运营标准话术至少要回答三件事：

- 我是谁：运营如何介绍青藤平台和自身角色。
- 怎么用：医生、患者、运营分别怎么使用平台。
- 怎么合规拿到收益：医生是承接平台委托的报告解读/知识服务，不是拿开单费。

关键要求：

- 禁止把话术写成“临床医生给平台开单，平台给开单费”。
- 应表达为“医生与平台彼此赋能，医生用闲暇时间提供非医疗性知识服务或报告解读服务，平台支付相应劳动报酬”。
- 输出后先发涂丰涛做合规审核。

## 原方案应改成什么方案

### 原方案

```text
线下医生推荐患者
  -> 医生生成个人问诊二维码
  -> 患者扫码进入互联网医院问诊并支付
  -> 患者完成检查
  -> 报告回到同一线下医生
  -> 医生解读自己的患者报告
  -> 平台按解读报告向该医生结算服务费
```

主要问题：推荐、检查成交、报告回派、服务费结算可以被串成一条 1:1 利益链。

### 新方案

```text
医生端预录入检查建议
  -> 患者自主进入青藤平台
  -> 系统按手机号/姓名/身份证等信息自动匹配医生预录入内容
  -> 患者确认项目、机构、价格并支付
  -> 互联网医院完成问诊确认与医疗留痕
  -> 患者完成线下检查
  -> 医生自己的患者报告通过运营/患者复诊等方式回看
  -> 平台另行向医生交叉派发非本人患者的报告解读任务
  -> 医生完成真实解读服务
  -> 平台按解读服务记录结算劳动报酬
```

方案关键词：

- 前链路：患者自主进入平台，医生只做检查建议和信息预录入。
- 中链路：支付前展示项目、机构和价格，支付后完成互联网医院问诊留痕。
- 后链路：报告查看与解读结算分离。
- 结算链路：交叉派单、真实服务、服务记录、弱化签名、患者评价。

## 待确认事项

1. 患者入口最终采用通用二维码、平台搜索、医生侧预录入后短信/链接触达，还是多方式并存。
2. 三甲医院、民营医院、诊所是否允许展示第三方平台二维码。
3. 患者端支付到底展示在问诊前的哪个页面，如何避免“一进入就强制付款”的体验问题。
4. 交叉派单规则是否需要跨省、跨机构、跨医生池，还是只需打断 1:1 对应。
5. 医生端报告解读任务是否需要显示患者省份、机构、年龄、性别、主诉、检查项目等字段。
6. 医生自己的患者报告回看，由运营微信推送、患者复诊出示，还是后续做独立非结算入口。
7. 医生服务费标准按 CT/MRI 等项目差异化，还是按解读任务类型分层。
8. 平台短期代收代付与长期互联网医院主体收款的合同和开票改造方案。
