# 活动管理 PRD（价格规则管理版）

**文档状态**: Draft  
**需求名称**: 活动管理 / 价格规则管理
**负责人**: 胡高鹏
**创建日期**: 2026-05-23  
**最近更新**: 2026-06-27

## 1. 背景

本次调整来自活动管理需求讨论会议。会议明确：当前活动管理不能继续按“交付中心促销活动”建模，而应按“互联网医院侧价格规则”建模。

当前已确认的业务现状：

- 同一产品在不同渠道当前只能展示一个统一价格，无法支持“平安”等特定平台不同价。
- 当前不支持针对特定用户群发放折扣券、优惠券或特殊折扣。
- 当前不支持多个项目组合后的组套优惠价。
- “一脉”中心与“青藤自助开单”存在价格展示口径不一致问题，需要区分用户展示价、系统记录价与结算/抽成口径。

补充会议纪要确认的价格调整场景：

1. 互联网医院侧不同平台不同价格。
2. 用户侧优惠券 / 折扣券。
3. 组套优惠。

因此，本模块需要从“活动价录入工具”升级为“价格规则配置工具”，让运营能够按业务通道、来源平台、签约交付中心、项目/套餐、用户条件等维度维护价格规则。

## 2. 问题定义

当前旧方案的问题：

- 主对象错误：旧方案以“交付中心 / 机构”为活动主体，容易误解为青藤直接响应各交付中心促销。
- 作用范围不清：会议已明确“不同渠道不同价格”的作用对象是“互联网医院渠道”，不是具体交付中心。
- 场景覆盖不足：旧方案只支持项目活动价，无法承载平台差异价、用户优惠、组套优惠。
- 价格口径混杂：展示价、系统记录价、结算价、抽成比例没有拆开，容易导致一脉、青藤自助开单等场景继续出现价格不一致。

影响对象：

- 平台运营：无法统一配置复杂价格规则。
- 互联网医院渠道：无法针对不同来源平台设置差异价格。
- 签约交付中心：无法清晰知道自己是否参与某个规则。
- 用户端：支付前展示价、优惠价、套餐价可能与系统记录价不一致。
- 财务 / 结算：缺少可追溯的价格口径与抽成配置。

## 3. 目标

### 业务目标

- 建立互联网医院侧的价格规则管理能力。
- 支持不同平台不同价格、用户侧优惠券 / 折扣券、组套优惠三类核心场景。
- 支持在“互联网医院”业务通道下，为特定“签约交付中心”的特定项目设置活动价格。
- 明确展示价、系统记录价、结算价和抽成比例的边界。

### 用户目标

- 运营可以在一个入口查看、创建、编辑、上架、下架价格规则。
- 运营可以明确配置规则类型、业务通道、来源平台、适用签约交付中心、适用项目/套餐、生效时间和规则价格。
- 运营可以在详情页核查某条规则的作用范围、价格变化和冲突情况。

### 交付目标

- 调整 PC 后台活动管理页面，使页面表达“价格规则管理”的新模型。
- 更新 PRD 与页面标注，避免继续沿用“交付中心活动价”的错误口径。
- 当前 demo 仍使用本地存储，不接入真实后端。

## 4. 非目标

- 不在本次实现真实价格引擎。
- 不在本次接入真实用户券发放系统。
- 不在本次接入真实支付、结算和财务系统。
- 不在本次完成一脉 / 青藤自助开单抽成比例调整的后端联调。
- 不在本次处理复杂审批流、批量导入导出、规则灰度发布。

## 5. 核心对象模型

### 5.1 业务通道

价格规则首先归属于业务通道。当前重点业务通道为：

- 互联网医院。
- 一脉中心。
- 青藤自助开单。

其中，本次主要解决“互联网医院侧不同平台不同价格”。

### 5.2 来源平台 / 合作平台

来源平台表示同一业务通道下的不同合作来源，例如：

- 全部平台。
- 平安。
- 青藤自营。
- 一脉。
- 其他合作平台。

“平安”等特定来源平台可对同一项目配置不同展示价格。

### 5.3 适用签约交付中心

交付中心不是价格活动主体，只是规则的适用范围。

正确表述：

> 在“互联网医院”业务通道下，为特定“签约交付中心”的特定项目设置价格规则。

### 5.4 适用项目 / 组套

规则可以作用于：

- 单个标准项目。
- 多个标准项目组成的组套。
- 后续可扩展到加收项、耗材、药品等。

### 5.5 价格口径

每条价格规则需要明确以下口径：

- 门市价 / 原价：项目基础价格。
- 展示价：用户端看到的价格。
- 支付价：用户实际支付价格。
- 系统记录价：内部系统记录的价格。
- 结算价：用于与交付中心、合作方或平台结算的价格。
- 抽成比例：如青藤自助开单从 25% 调整至 30%。

## 6. 价格规则类型

### 6.1 不同平台不同价格

用于解决“互联网医院侧不同平台不同价格”。

示例：

- 业务通道：互联网医院。
- 来源平台：平安。
- 适用签约交付中心：成都高新影像交付中心。
- 项目：肺结节 AI 辅助筛查。
- 展示价：129 元。
- 其他平台仍展示默认价格或其他规则价。

### 6.2 项目活动价格

用于在互联网医院渠道下，为特定签约交付中心设置特定项目活动价。

注意：

- 青藤统一管理规则。
- 各交付中心自行决定是否参与及如何促销。
- 不应理解为青藤直接响应每个交付中心的促销活动。

### 6.3 用户侧优惠券 / 折扣券

用于针对用户、人群、订单或券码提供优惠。

需要配置：

- 适用用户范围：全部用户、指定用户、用户标签、人群包、渠道用户等。
- 优惠方式：满减、折扣、固定优惠金额。
- 使用门槛：项目、套餐、订单金额、生效时间、每人可用次数。
- 叠加规则：是否可与平台差异价、项目活动价、组套优惠叠加。

### 6.4 组套优惠

用于多个项目组合后的套餐价。

需要配置：

- 组套名称。
- 组成项目。
- 套餐展示价。
- 套餐明细价。
- 下发到交付中心时是一条套餐项目，还是拆分为多个执行项目。
- 如果拆分下发，需要说明价格是否分摊、如何分摊。

## 7. 一脉 / 青藤自助开单价格一致性处理

会议结论：

- 青藤自助开单抽成比例从 25% 调整至 30%。
- 一脉所有项目均按实际门市价展示。
- 系统内记录 7 折后的价格。

产品处理原则：

- 这不是普通活动价，不应建成一条“项目活动价格”。
- 应作为价格口径 / 结算配置管理。
- 活动管理页面可以展示该类规则影响，但底层应区分展示价、系统记录价和结算价。

## 8. 页面方案

### 8.1 列表页

页面标题：活动管理
页面副标题：统一管理互联网医院侧价格规则，覆盖平台差异价、用户优惠券 / 折扣券、组套优惠和项目活动价。

表格字段：

- 序号。
- 价格规则名称。
- 规则类型。
- 业务通道。
- 来源平台。
- 适用签约中心。
- 中心数。
- 项目 / 组套数。
- 生效时间。
- 状态。
- 优先级。
- 更新时间。
- 操作。

操作：

- 查看。
- 编辑。
- 上架。
- 下架。
- 删除。

### 8.2 新建 / 编辑页

基础信息字段：

- 价格规则名称。
- 价格规则类型。
- 业务通道。
- 来源平台 / 合作平台。
- 适用签约交付中心。
- 生效时间。
- 规则说明。

适用项目与规则价格区域：

- 按签约交付中心切换。
- 为每个中心选择适用项目。
- 为每个项目录入规则价。
- 不同规则类型下，规则价含义不同：
  - 平台差异价：来源平台展示价。
  - 项目活动价：中心项目活动价。
  - 用户优惠：优惠后价或折扣后价。
  - 组套优惠：套餐总价或套餐内项目分摊价。

### 8.3 项目库弹窗

弹窗名称：平台标准项目库。

用途：

- 为当前签约交付中心选择适用项目。
- 已添加项目禁选。
- 与同类型价格规则冲突的项目禁选。

冲突提示文案：

> 同一业务通道、来源平台、签约交付中心、项目、规则类型在重叠时间内只能存在一条有效价格规则。不同规则类型可并存，但需由优先级和叠加规则决定最终成交价。

### 8.4 详情页

基础信息展示：

- 价格规则名称。
- 规则类型。
- 业务通道。
- 来源平台。
- 状态。
- 生效时间。
- 创建人。
- 更新时间。
- 适用签约交付中心。
- 中心数。
- 项目 / 组套数。
- 规则说明。

价格明细展示：

- 签约交付中心切换。
- 项目名称。
- 所属分类。
- 编码。
- 检查类型。
- 原价 / 门市价。
- 规则价。
- 价格变化。

## 9. 优先级与冲突规则

### 9.1 冲突禁止

以下条件完全相同且时间重叠时，不允许创建重复规则：

- 业务通道。
- 来源平台。
- 规则类型。
- 签约交付中心。
- 项目 / 组套。

### 9.2 可并存但需优先级

不同规则类型可同时存在，但必须由优先级和叠加规则决定最终价格。

建议默认优先级：

1. 组套优惠。
2. 用户侧优惠券 / 折扣券。
3. 不同平台不同价格。
4. 项目活动价格。
5. 门市价 / 基础价。

### 9.3 待明确叠加规则

仍需业务确认：

- 用户券是否可叠加项目活动价。
- 用户券是否可叠加组套优惠。
- 平台差异价与组套优惠同时命中时，以平台价组套为准，还是以普通组套价为准。
- 组套拆分下发时，价格如何分摊到项目明细。

## 10. 保存校验规则

- 价格规则名称不能为空。
- 价格规则类型不能为空。
- 业务通道不能为空。
- 来源平台不能为空。
- 至少选择 1 个适用签约交付中心。
- 生效开始和结束时间不能为空。
- 结束时间必须晚于开始时间。
- 每个适用签约交付中心至少选择 1 个项目。
- 每个项目必须填写规则价。
- 不允许与同类型、同范围、同项目、重叠时间的有效规则冲突。

## 11. 数据与指标

核心验证指标：

- 运营可成功创建不同平台不同价格规则。
- 运营可成功创建用户优惠券 / 折扣券规则。
- 运营可成功创建组套优惠规则。
- 运营可在详情页核查价格规则适用范围与价格变化。
- 冲突规则可阻止同类型重复配置。

观察指标：

- 价格规则创建成功率。
- 价格规则上下架成功率。
- 价格规则冲突命中次数。
- 用户端价格展示一致性问题反馈数。

## 12. 风险与依赖

技术依赖：

- 真实价格引擎。
- 用户券系统。
- 项目 / 组套主数据。
- 订单价格计算链路。
- 结算系统。

产品风险：

- 若不明确叠加规则，用户端可能出现多条价格规则同时命中但无法判断最终价格。
- 若不区分展示价和系统记录价，一脉 / 青藤自助开单价格一致性问题会继续存在。
- 若继续把交付中心作为活动主体，后续平安等平台差异价会无法表达。
