# PM能力层赋能建设 - 原型说明

本原型说明文档对应以下 agent 与 tool：

- Agent：`01_agents/角色定义/原型设计助手.md`
- Agent：`01_agents/角色定义/Context架构师.md`
- Tool：`02_tools/工作流/产品需求从想法到沉淀.md`

## 1. 原型目标

本次不是做前端页面原型，而是做“目录结构原型”。核心目的是让仓库中的能力层、知识层、工作层边界清楚，且阅读路径明确。

## 3. 用户使用路径

### 路径一：新需求启动

1. 先找合适角色
2. 再套合适模板
3. 在 `04_workspace/prd/某个专题/analysis/` 落分析
4. 再输出 `prototype/` 与 `prd/`

### 路径二：日常会议整理

1. 用 `会议纪要整理员`
2. 套 `会议纪要整理模板`
3. 落到 `04_workspace/关键会议纪要/` 或具体专题 `analysis/`

### 路径三：原型设计

1. 用 `原型设计助手`
2. 明确页面结构、流程和关键状态
3. 落到专题 `prototype/`，或给 `04_workspace/demos/` 提供实现依据

### 路径四：demo 自查

1. 用 `Demo验收助手`
2. 套 `Demo验收清单`
3. 输出验收记录

## 4. 验收标准

- 新用户第一次进入仓库时，能快速看懂“由谁做、按什么做、放到哪里”
- `01_agents/` 和 `02_tools/` 不与 `04_workspace/` 或 `03_context/` 职责重叠
- 任意一个真实需求，都能被映射到“agent + tool + 专题目录”的组合
