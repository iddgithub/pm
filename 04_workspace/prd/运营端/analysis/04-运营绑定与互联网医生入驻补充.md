# 运营绑定与医生入驻补充需求分析

## 记录说明

- 整理时间：2026-05-08
- 当前归属：运营端
- 输入来源：本轮移动端三页原型设计与批注调整
- 当前性质：在既有四角色体系下，补齐运营绑定、运营人员管理和互联网医生入驻三类角色链路

## 一句话概述

本次补充方案把“医生报告解读服务”从单一医生端任务处理，扩展为“运营绑定医生 -> 运营监控订单与提现 -> 互联网医生注册入驻”的前置管理闭环。

## 本次新增角色

### 1. 互联网医生

- 通过注册页面提交身份信息、执业信息和必要资质材料。
- 审核通过后，可成为报告解读服务的承接医生。
- 后续可通过医生绑定码被运营人员绑定和管理。

### 2. 运营人员

- 扫描医生绑定码，建立“运营人员 - 医生”的绑定关系。
- 查看自己的提现金额和绑定医生数量。
- 按订单状态查看已绑定医生名下患者检查订单。
- 关注患者检查订单从支付、检查、出报告到解读的状态流转。

### 3. 平台

- 负责医生入驻资质审核。
- 负责运营与医生绑定关系维护。
- 负责检查订单、报告解读服务费和运营提现数据汇总。

## 页面范围

### 1. 医生二维码页面

页面目标：给医生生成绑定码，运营人员扫码后建立绑定关系。

当前原型表达：

- 页面只展示医生绑定码和二维码。
- 刷新按钮用于重新生成或刷新绑定码。
- 二维码作为唯一核心信息，避免展示过多医生身份与收益数据。

建议规则：

- 二维码需有有效期，过期后需要刷新。
- 同一医生可绑定多个运营或仅允许绑定一个运营，需要业务确认。
- 扫码后是否需要医生确认，需要业务确认。

### 2. 运营人员页面

页面目标：让运营人员管理自己绑定的医生、患者检查订单和提现收益。

当前原型表达：

- 顶部为“检查检验 / 我的管理”切换。
- 支持扫码绑定医生。
- 展示我的提成和绑定医生数量。
- 支持按月份筛选。
- 搜索框支持输入姓名和手机号。
- 支持订单状态筛选：全部、已支付、已检查、已出报告、已解读。
- 订单卡片展示患者、医生、手机号、项目数、金额、时间和状态。

状态口径：

- 已支付：患者已完成支付，检查订单成立。
- 已检查：检查项目已完成。
- 已出报告：正式报告已出具。
- 已解读：医生已完成报告解读服务。

本轮已删除“已取消”作为筛选项，说明当前运营工作台先聚焦有效订单链路。

### 3. 互联网医生注册页面

页面目标：让互联网医生提交入驻审核所需的核心必要信息。

当前原型表达：

- 身份信息：手机号、真实姓名、身份证号。
- 执业信息：所在医院、科室、职称、执业证书编号、擅长方向。
- 材料上传：医师执业证、资格证/职称证、本人证件照。
- 所有必要字段前用红色 `*` 标记。
- 材料上传项下方展示收集原因：
  - 医师执业证：用于核验当前执业资格与执业地点。
  - 资格证/职称证：用于确认医生专业资质与职称等级。
  - 本人证件照：用于实名认证和账号归属核验。

本轮已删除银行卡信息，说明注册阶段先聚焦资质审核；提现银行卡可后置到结算/账户设置流程。

## 关键业务关系

```text
互联网医生注册入驻
  -> 平台审核医生资质
  -> 医生生成绑定码
  -> 运营扫码绑定医生
  -> 运营查看绑定医生名下患者检查订单
  -> 订单进入已支付 / 已检查 / 已出报告 / 已解读状态
  -> 平台汇总运营提成和医生服务费
```

## 与原医生报告解读服务的关系

- 原专题已覆盖医生侧“报告解读任务、确认解读内容、服务费汇总、打款记录”。
- 本次补充覆盖该服务的上游管理链路：
  - 谁可以成为解读医生。
  - 运营如何绑定医生。
  - 运营如何跟踪绑定医生带来的患者检查订单和收益。
- 两部分合并后，形成从医生入驻、运营绑定、检查订单跟踪到报告解读结算的闭环。

## 待确认问题

1. 医生绑定码是一人一码长期有效，还是每次刷新生成短期码。
2. 一个医生是否可以被多个运营绑定。
3. 运营绑定医生后，是否能看医生所有患者订单，还是仅看自己推广来源订单。
4. 运营提现金额的计算口径是按订单提成、按报告解读服务费提成，还是两者都有。
5. 医生注册审核通过后，是否需要补充银行卡，还是首次提现时再补充。
6. 医生资质材料是否需要后台人工审核，以及审核不通过时如何修改重提。
