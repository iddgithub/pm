# 04_workspace/prd 维护说明

本目录采用“专题目录制”，用于记录每个需求从分析、原型到 PRD 的完整过程，而不是把所有文档平铺在根目录。

## 标准结构

```text
04_workspace/prd/
├── README.md
├── PRD模板.md
├── 需求专题A/
│   ├── README.md
│   ├── analysis/
│   ├── prototype/
│   └── prd/
└── 需求专题B/
    ├── README.md
    ├── analysis/
    ├── prototype/
    └── prd/
```

## 命名约定

- 专题目录：直接使用需求主题命名
- 分析文档：`01-需求分析.md`
- 原型文档：`01-原型说明.md`
- PRD 文档：`01-PRD.md`
- 沟通记录：`YYYY-MM-DD-沟通记录.md`

## 使用顺序

1. 先在 `analysis/` 做需求分析和规则澄清。
2. 再在 `prototype/` 整理页面结构和交互方案。
3. 最后在 `prd/` 输出正式 PRD。

## 当前专题

- `患者端/`：独立承接患者查看报告、查看解读内容与提交评价页面，便于单独调整患者侧原型方案
- `互联网医生端/`：独立承接互联网医生侧诊前问诊页面，便于单独调整互联网医生端原型方案
- `运营端/`：独立承接运营绑定、订单查看与医生入驻页面，便于单独调整运营侧原型方案
- `检查项目多对多对码/`：独立承接检查项目主数据、上下游映射、组合匹配和异常处理专题
- `医生合规开单/`：统一承接医生合规开单专题，并吸收原 `诊所医生端/` 的线下录入、机构选择、开单确认、问诊入口与解读链路
